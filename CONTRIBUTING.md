# Как участвовать

## Ветки и PR

- Работа ведётся в ветках `feature/<название>`, `fix/<название>`, `chore/<название>` от `develop`.
- Изменения попадают в `develop` только через pull request. Для слияния нужны одно одобрение и зелёный CI.
- Релизы: слияние `develop` в `main` с тегом версии.
- После слияния ветка удаляется.

## Коммиты

Формат conventional commits: `тип: краткое описание` на английском.

Типы: `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `style`, `ci`.

Пример: `feat: add task deadline reminders`.

## Перед PR

```sh
npm run format:check
npm run lint -- --max-warnings=0
npm run typecheck
npm test
npm run build
```

Те же проверки выполняет CI. Для UI дополнительно проверьте клавиатуру и мобильную ширину; для изменений схемы БД — миграцию на пустой базе (`npm run db:reset`).

## Окружение

- Версия Node.js берётся из `.node-version`.
- После `git pull` выполняйте `npm install`: он устанавливает зависимости и git-хуки (Husky, lint-staged). Хуки форматируют и проверяют только изменённые файлы.
- Форматирование — Prettier с настройками из `.prettierrc.json`. Редактор должен использовать его как форматтер; для VS Code настройки уже лежат в `.vscode/`.
- Файлы `.env` не коммитятся. Новые переменные окружения добавляйте в `.env.example` без значений.
