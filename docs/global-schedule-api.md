# Контракт API глобального расписания

Статус: спецификация для реализации. Маршрута пока нет; страница
`/schedule/global` показывает демонстрационные данные.

`GET /api/schedule/global?course=3&from=2026-09-14&to=2026-09-20`

## Запрос

- `course` — обязательное целое число от 1 до 10, как при импорте расписания.
  Нынешний интерфейс предлагает курсы 1–4.
- `from`, `to` — обязательные существующие даты `YYYY-MM-DD`. Границы
  включительные; период составляет от 1 до 7 дней. Необязательно начинать
  его с понедельника.
- Каждый параметр передаётся ровно один раз. Посторонние параметры, включая
  `groupId`, `userId`, `kind` и `status`, отклоняются.
- Требуется действующая сессия. Группа в профиле пользователя не требуется:
  глобальное расписание доступно всем вошедшим пользователям.

## Успешный ответ

```json
{
  "course": 3,
  "from": "2026-09-14",
  "to": "2026-09-20",
  "timeZone": "Europe/Chisinau",
  "groups": [
    { "id": "group-1", "name": "TI-241" },
    { "id": "group-2", "name": "TI-242" }
  ],
  "days": [
    {
      "date": "2026-09-14",
      "groupStates": [
        {
          "groupId": "group-1",
          "status": "LESSONS",
          "week": { "number": 3, "parity": "ODD" },
          "scheduleId": "schedule-1",
          "holidays": []
        },
        {
          "groupId": "group-2",
          "status": "LESSONS",
          "week": { "number": 3, "parity": "ODD" },
          "scheduleId": "schedule-1",
          "holidays": []
        }
      ],
      "lessons": [
        {
          "id": "lesson-1:2026-09-14",
          "lessonId": "lesson-1",
          "scheduleId": "schedule-1",
          "groupIds": ["group-1", "group-2"],
          "startMinutes": 585,
          "endMinutes": 675,
          "subject": {
            "id": "subject-1",
            "name": "Математика",
            "colorKey": "blue"
          },
          "type": "LECTURE",
          "teacher": "И. Иванов",
          "classroom": "301",
          "topic": null
        }
      ]
    }
  ]
}
```

`days` содержит каждый день запрошенного периода, включая выходные. Для каждого
дня `groupStates` содержит по одной записи для каждой группы из `groups`:

- `NOT_PUBLISHED` — в эту дату у группы нет действующего опубликованного
  расписания; `week` и `scheduleId` равны `null`, `holidays` пуст.
- `HOLIDAY` — действует период без занятий; `holidays` содержит объекты
  `{ id, name }`, занятий для группы в этот день нет.
- `NO_LESSONS` — расписание действует, но подходящих занятий нет.
- `LESSONS` — есть хотя бы одно подходящее занятие.

`week` содержит номер и чётность учебной недели либо `null` при отсутствии
действующего расписания. Это поле принадлежит группе: у разных опубликованных
расписаний может быть разный учебный год и начало отсчёта недель.

`lessons` содержит каждый экземпляр занятия один раз на дату. Общая лекция
передаётся с несколькими `groupIds`, без копии на каждую группу. Если для одной
группы в одно время проходят два варианта занятия, возвращаются обе записи.
`groupIds` содержит только группы из `groups`, для которых занятие действительно
в эту дату. Клиент может объединить соседние колонки общей лекции по одному
`id`; API не передаёт `colSpan`, поскольку он зависит от выбранного фильтра и
порядка колонок.

Группы определяются по получателям занятий опубликованных расписаний `GLOBAL`
выбранного курса, пересекающих запрошенный период. Группа без занятий во всём
расписании в текущей схеме БД не представлена и в `groups` не попадает.
`groups` сортируется по имени, дни — по дате, занятия — по времени начала,
окончания и `lessonId`.

## Правила выборки и расчёта

Читаются только записи `ScheduleImport` со статусом `PUBLISHED`, типом `GLOBAL`
и выбранным `course`. Дата занятия должна входить одновременно в период
расписания, семестра и учебного года. Отсчёт чётности начинается с
`firstOddWeekMonday`; каникулы его не сбрасывают. Время занятий остаётся в
минутах местного времени университета и не переводится в часовой пояс браузера.

Два действующих опубликованных расписания для одной группы на одну дату —
конфликт, даже если занятия не пересекаются по времени. Расписания разных групп
могут действовать одновременно. Если опубликованных расписаний для курса нет,
ответ успешный: `groups: []`, а у каждого дня пустые `groupStates` и `lessons`.

## Ошибки и кэширование

| HTTP | Ответ               | Условие                                              |
| ---- | ------------------- | ---------------------------------------------------- |
| 400  | `INVALID_QUERY`     | Некорректный курс, даты, длина периода или параметры |
| 401  | `UNAUTHORIZED`      | Нет сессии или пользователь удалён                   |
| 409  | `SCHEDULE_CONFLICT` | Несколько расписаний одной группы на одну дату       |
| 500  | `INTERNAL_ERROR`    | Ошибка БД или некорректные сохранённые данные        |

Ошибка возвращает объект `{ "code": "...", "message": "..." }` без деталей БД.
Для всех ответов: `Cache-Control: private, no-store` и `Vary: Cookie`.
