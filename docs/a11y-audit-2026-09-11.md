# StudyFlow: аудит доступности (a11y) и варианты дизайна

Срез: ветка `imurd @ 2f78d6a`, 11 сентября 2026. Проверены все 10 маршрутов: статический разбор 60 файлов `app/` и `components/`, живой прогон axe-core 4 (наборы WCAG 2.0/2.1/2.2 A+AA и best-practice) через Playwright на собранном приложении с сидированной базой, расчёт контрастов по всем используемым парам цветов Tailwind.

Целевой уровень: **WCAG 2.2 AA**. Дополнительно оценены критерии 2.2, которых нет в 2.1: 2.4.11 «Фокус не перекрыт», 2.5.8 «Размер цели 24×24».

---

## 0. Резюме

Проект **лучше среднего студенческого прототипа**: семантические таблицы в расписании, Radix-диалоги с фокус-ловушкой, `aria-current` в навигации, `aria-live` для вычисляемых оценок, формы задач и входа с `aria-invalid`/`aria-describedby`. Основание крепкое. Проблемы концентрируются в четырёх местах: **палитра** (серые и цветные оттенки `-400/-500` не проходят контраст), **индикатор фокуса** (кольца `blue-100` невидимы), **самодельные виджеты** (селект задач, вкладки входа, ответы квиза без ролей) и **отсутствие настроек восприятия** (нет тёмной темы, нет `prefers-reduced-motion`, нет skip-link).

| Область                 | Оценка | Комментарий                                                                      |
| ----------------------- | ------ | -------------------------------------------------------------------------------- |
| Структура и ориентиры   | хорошо | header/nav/main есть; нет skip-link, два `<h1>` на /tasks, 4 маршрута без title  |
| Клавиатура и фокус      | средне | Radix спасает диалоги; кольца фокуса `blue-100` ≈ 1,2:1, невидимы                |
| Семантика виджетов      | слабо  | селект задач, вкладки входа, ответы квиза, дата-пикер без ролей/клавиш           |
| Контраст                | слабо  | 62 узла провалили axe; `gray-400`, `emerald-500`, `amber-500/600`, `red-500`     |
| Формы                   | хорошо | лучшие места проекта; серверные ошибки не объявляются                            |
| Динамика (live, motion) | средне | 10 `aria-live`, но нет анонсов генерации квиза и загрузки; `motion-reduce` 1 раз |
| Настройки восприятия    | нет    | нет тёмной темы, контрастной темы, масштаба шрифта                               |

**Что делать.** Три версии дизайна ниже — не альтернативы, а ступени. Версия A закрывает AA без визуальных изменений за 2–3 дня и должна войти в develop до октябрьского дедлайна. Версия B добавляет пользовательские режимы поверх токенов. Версия C — инклюзивный редизайн, пригодный как отдельная глава диплома.

### 1.2 Видимость фокуса (2.4.7, 2.4.11, 2.4.13)

- 12 контролов используют `outline-none` + `focus:ring-blue-100` или `ring-blue-200` (LoginForm, RegisterForm, materials, upload-material-dialog). Кольцо `#dbeafe` на белом ≈ 1,2:1 — фокуса не видно вообще.
- Базовые `Button` и `Textarea` рисуют кольцо в 1px без offset; на синей кнопке синее кольцо сливается.
- Скрытый `sr-only` file-input в диалоге загрузки получает фокус, но ничего не подсвечивается.
- Липкая шапка `h-16` без `scroll-margin-top` перекрывает элемент, получивший фокус снизу (новый критерий 2.4.11).

### 1.3 Семантика самодельных виджетов (4.1.2, 1.3.1, 2.1.1)

### 1.4 Ориентиры, заголовки, заголовки страниц (2.4.1, 2.4.2, 1.3.1)

- Skip-link отсутствует; каждая страница начинается с 9 ссылок сайдбара.
- Два `<h1>` на /tasks (Header и страница). `CardTitle` рендерит `div`, `EmptyState`/`ErrorState` жёстко `h4` — outline заголовков рвётся.
- Без `metadata.title`: dashboard, tasks, gpa, auth. Все четыре в табе называются «StudyHub».
- Подменю «Расписание» свёрнуто, даже когда пользователь находится на `/schedule/global`: пункт с `aria-current` скрыт.

### 1.5 Динамика (4.1.3, 2.2.2, 2.3.3)

- Нет объявлений: генерация квиза (2,2 с), смена экрана квиз → результаты, смена вкладки вход/регистрация, серверные ошибки авторизации, `LoadingIndicator`, `ErrorState`, тост в материалах (сам исчезает через 2,5 с).
- Обратное: `aria-live` на **каждой** карточке предмета — при смене семестра N одновременных объявлений.
- Вечный `animate-spin` как индикатор статуса «в работе» на карточках задач (2.2.2).
- `motion-reduce:` встречается один раз в проекте; глобального `prefers-reduced-motion` нет. Классы `animate-in`, `zoom-in-95` в диалогах мёртвые — плагин анимаций не подключён.

### 1.6 Размер целей (2.5.8, новое в 2.2)

Кнопка закрытия во **всех** диалогах — голая иконка 16×16 без паддинга. Переключатель статуса задачи ровно 24×24, удаление предмета ≈ 24. Остальное проходит.

### 1.7 Что сделано хорошо (сохранить как эталон)

- `week-grid.tsx` и `global-schedule.tsx`: настоящая `<table>`, `th scope`, `aria-current="date"`, `sr-only` «Нет занятий», прокручиваемая область с `tabIndex={0}` и именем.
- `task-dialog.tsx`: `htmlFor`/`id`, `aria-invalid`, `aria-describedby → role="alert"`, фокус на первое невалидное поле.
- `subject-cards.tsx`: полный `progressbar` с `aria-valuetext` «8,5 из 10» и единственный `motion-reduce`.
- `subject-card.tsx` в AI Coach: правильный `radiogroup`/`radio` — образец для квиза.
- `lesson-card.tsx`: карточка-кнопка с полным `aria-label` и явным кольцом фокуса.
- Ни один статус не передаётся только цветом в задачах, оценках и расписании (1.4.1 выполнен).
- Навигация: `aria-current`, `aria-expanded`/`aria-controls` с `useId`, `hidden` на панели.
- Radix Dialog везде, где нужен модальный слой, включая мобильное меню.

## 2. Три версии дизайна для доступности

### Версия A — «AA без редизайна» (2–3 дня, до октябрьского дедлайна)

Цель: пройти axe и ручную клавиатурную проверку на всех маршрутах. Визуально пользователь почти не заметит изменений.

**A1. Токены цвета с ролями.** В `globals.css` вводится правило: текст — не светлее `-600`, интерактивные иконки — не светлее `-500`, заливка статусов — `-600/-700`, подложки — `-50/-100`. Все `gray-400`/`slate-400` в тексте → `gray-500`/`slate-600`; `red-500` → `red-700`; `emerald-500/600` → `emerald-700`; `amber-500/600` → `amber-700`; `rose-400/600` → `rose-700`. Семантические токены `--success`, `--warning`, `--danger`, `--info` вместо прямых Tailwind-классов.

```css
:root {
  --fg-muted: #4b5563; /* gray-600, 7.6:1 */
  --fg-subtle: #6b7280; /* gray-500, 4.8:1 — только ≥ 14px */
  --success: #047857; /* emerald-700, 5.9:1 */
  --warning: #b45309; /* amber-700, 5.0:1 */
  --danger: #b91c1c; /* red-700, 6.5:1 */
  --focus: #1d4ed8; /* blue-700 */
}
```

**A2. Единый индикатор фокуса.** Один глобальный стиль вместо 27 вариантов `outline-none`:

```css
:where(a, button, input, select, textarea, [tabindex]):focus-visible {
  outline: 2px solid var(--focus);
  outline-offset: 2px;
}
:where(main) :where(h1, h2, h3, [tabindex]) {
  scroll-margin-top: 5rem;
}
```

Убрать `focus:ring-blue-100/200` в 12 местах; в `Button`/`Textarea` заменить `ring-1` на `ring-2 ring-offset-2`.

**A3. Ориентиры.** Skip-link первым элементом `body`, `<main id="main" tabIndex={-1}>`, `metadata.title` для четырёх маршрутов, один владелец `<h1>` (Header), `as`-проп у `CardTitle`, `EmptyState`, `ErrorState`.

**A4. Виджеты.** `CustomSelect` → Radix Select; `AuthTabs` → tablist; ответы квиза → radiogroup; `isSubmitted` протянуть или удалить; статус задачи → `aria-pressed`; `DialogClose` → `size-9`; «Забыли пароль?» → Link или удалить.

**A5. Динамика.** `role="status"` в `LoadingIndicator`, `role="alert"` в `ErrorState` и ошибках загрузки; анонс «Готово, N вопросов» после генерации; фокус на заголовок нового экрана квиза/результатов; один live-регион на страницу оценок; глобальный блок:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

**A6. Регресс-гейт.** Добавить `@axe-core/playwright` в devDependencies и спек, падающий на любом нарушении A/AA. Шаблон уже отработан в этом аудите (см. раздел 5).

Ожидаемый результат: 0 нарушений axe на 10 маршрутах, полная клавиатурная навигация без мыши.

### Версия B — «Режимы восприятия» (1–2 недели, после Версии A)

Цель: дать пользователю управлять контрастом, движением и размером. Всё строится на токенах Версии A, поэтому компоненты не переписываются.

**B1. Тёмная тема.** Сейчас `dark:` встречается 15 раз без определения тёмных токенов, то есть не работает. Ввести `[data-theme="dark"]` с полной палитрой и `prefers-color-scheme` по умолчанию. Проверить оба состояния тем же axe.

**B2. Режим высокого контраста.** `[data-contrast="high"]`: чёрный текст на белом, границы `gray-700` вместо `gray-200` (сейчас 1,24:1 — карточки не видны при слабом зрении), заливки статусов насыщенные, фокус 3px. Respect `prefers-contrast: more`.

**B3. Масштаб текста и плотность.** Базовый размер 16px через `html { font-size }`, переключатель 100/112/125 %. Убрать `text-[10px]` и `text-xs` из смысловых текстов (76 мест) — минимум 14px для контента, 12px только для меток. Проверка reflow на 320px и 200 % зума, особенно неделя расписания и диалоги (добавить `max-h-[85dvh] overflow-y-auto` в `DialogContent`).

**B4. Движение.** Настройка «Уменьшить анимацию» дублирует системную; статичная иконка для статуса «в работе» вместо вечного спиннера.

**B5. Страница «Настройки → Доступность».** Четыре переключателя: тема, контраст, размер текста, анимация. Хранение в `localStorage` и в профиле пользователя, когда появится бэкенд.

### Версия C — «Инклюзивный редизайн» (семестр, глава диплома)

Цель: доступность как исследуемое свойство, а не чек-лист. Подходит под тему диплома «влияние интервального повторения…»: студенты с дислексией и СДВГ — заметная часть аудитории самопроверки.

**C1. Кабинет, читаемый линейно.** Дашборд как список приоритетов (`<ol>`), а не сетка карточек равного веса. Каждая карточка — `article` с заголовком, время/предмет/аудитория — `dl`.

**C2. Расписание в трёх представлениях, выбираемых пользователем.** Таблица (есть), список по дням для скринридера и телефона, «только сегодня» крупным шрифтом. Единый источник данных, переключатель запоминается.

**C3. Квиз без гонки.** Один вопрос на экран, `radiogroup`, обратная связь текстом и иконкой, кнопка «Объяснить» рядом с ответом, без таймера (сейчас его нет — зафиксировать как принцип). Результаты — `dl` с разбором, а не цветные плитки.

**C4. Целевые размеры 44×44 на мобильном.** Пересмотреть плотность карточек задач, переключатели статуса, кнопки в материалах.

**C5. Многоязычность.** `lang="ru"` при английских «Dashboard», «AI Exam Coach», «Made by students for students»: либо `<span lang="en">`, либо перевод. Румынский и английский интерфейс — отдельная задача, но токены и строки готовить сейчас.

**C6. Шрифт и ритм.** Сейчас `body` набран Arial: `globals.css` ссылается на Geist, но макет его не подключает. Выбрать читаемый экранный шрифт с открытыми формами (Inter или Atkinson Hyperlegible для режима «дислексия»), межстрочный 1,5, ширина строки ≤ 75 знаков.

**C7. Исследовательский протокол.** Тест с 5–8 студентами: клавиатура, NVDA/VoiceOver, зум 200 %, режим высокого контраста. Метрики: время до первой задачи, число ошибок, SUS. Это даёт диплому измеримый результат.

## 5. Как воспроизвести прогон axe

Установить `@axe-core/playwright` в devDependencies и добавить спек в `tests/e2e/`:

```ts
import { test, expect } from "@playwright/test";
import AxeBuilder from "@axe-core/playwright";

const routes = [
  "/dashboard",
  "/tasks",
  "/schedule",
  "/schedule/global",
  "/schedule/assessments",
  "/gpa",
  "/gpa/calculator",
  "/materials",
  "/ai-coach",
];

for (const route of routes) {
  test(`a11y ${route}`, async ({ page }) => {
    await page.goto(route);
    const { violations } = await new AxeBuilder({ page })
      .withTags(["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22aa"])
      .analyze();
    expect(violations, JSON.stringify(violations, null, 2)).toEqual([]);
  });
}
```

Он ляжет в существующий job браузерных тестов CI без дополнительной инфраструктуры. Ограничение axe: он не видит проблем клавиатуры, фокуса и живых регионов — раздел 4 остаётся ручным чек-листом.

Локальная особенность: порт 5433 на машине аудита занят чужим Postgres, поэтому прогон выполнялся на временном контейнере с портом 5434. Для команды это не воспроизводится.
