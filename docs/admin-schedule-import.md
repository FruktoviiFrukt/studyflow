# Импорт и управление расписанием

Страница `/admin/schedule` подключена к PostgreSQL. Интерфейс использует общие
редакторы занятия, каникул и предпросмотра из ветки `feat/admin-panel`.

## Запуск

1. Применить миграции: `npx prisma migrate deploy`, затем
   `npx prisma generate`. Они добавляют исходный текст занятия, замечания импорта
   и тип расписания.
2. На сервере нужен Python с `pdfplumber`: установить зависимости командой
   `python -m pip install -r scripts/schedule-import/requirements.txt`.
3. Указать `SCHEDULE_PYTHON` (путь к Python, если его нет в PATH).
   На текущем компьютере в игнорируемый `.env` добавлен путь к доступному
   bundled Python. В Git этот локальный путь не отправляется.
4. При необходимости указать `SCHEDULE_UPLOAD_DIR`: по умолчанию
   `.data/schedule-pdfs`. Каталог закрыт от прямой раздачи и исключён из Git.
5. Запустить `npm run dev`, войти как пользователь с ролью ADMIN в БД.
   Если dev-сервер уже работал, перезапустить после изменения `.env`.

В деплое нужен постоянный диск для PDF и Python, доступный процессу Node.
Эта реализация не рассчитана на непостоянную файловую систему serverless.
При переносе на несколько экземпляров приложения нужен общий файловый store.

## Сценарий

Загрузить PDF (до 20 МБ, до 10 страниц), выбрать тип расписания, указать год,
курс и семестр. Для студенческого расписания и аттестаций также указать границы
периода и понедельник первой нечётной недели. При импорте `GLOBAL` эти даты
подставляются автоматически из существующего семестра, либо из границ семестра
нового учебного года. Если год/семестр отсутствуют,
сервер создаёт их. Год в этой версии сентябрь–август; границы нового семестра
берутся из введённого периода. Последующие импорты должны укладываться в него.
Существующее начало отсчёта года автоматически не меняется.

После импорта создаётся DRAFT. Исходник доступен по кнопке «Исходный PDF».
В режиме «Как в PDF» глобальный черновик показывает все группы в колонках,
с фильтрами потока и чётности недели. Пары можно открыть прямо из таблицы.
Все извлечённые занятия reviewed=false. В редакторе показан sourceText для
сверки. Можно искать по предмету, преподавателю и группе, менять получателей,
добавлять/удалять пары и каникулы. Правки локальные до «Сохранить черновик».
После сохранения они переживают обновление страницы. Публикация допускается
после сохранения при наличии хотя бы одного занятия. Непроверенные записи,
замечания импорта и одновременные занятия остаются видимыми для сверки.

Тип и статус сохраняются в БД; список в админке фильтруется по ним. Ранее
загруженные расписания получают тип «Расписание студентов». Студенческий API
читает только опубликованные расписания этого типа. Глобальная страница читает
опубликованные расписания типа `GLOBAL` через отдельный API. Страница аттестаций
ещё не подключена к реальным данным; при загрузке её PDF пока используется тот
же парсер учебного расписания.

Публикация студенческого расписания делает данные доступными `/api/schedule`. Возврат в черновик скрывает
их. Повторный PDF создаёт новый черновик; опубликовать его для тех же групп и
пересекающихся дат можно только после снятия прежней публикации. Старый черновик
можно удалить вместе с его занятиями, каникулами и сохранённым PDF. Исходный PDF
на компьютере пользователя не затрагивается.

## Возможности и ограничения парсера

`scripts/schedule-import/parse_pdf.py` использует геометрию линованной таблицы:
заголовки групп, подписи дней и интервалы времени. Объединённые колонки дают
несколько получателей одного занятия. Верхняя половина интервала — odd,
нижняя — even. Ячейка на две пары становится одним длинным интервалом.
Если извлекатель таблицы разделил текст внутри видимой ячейки, части
объединяются до разбора предмета, преподавателя и аудитории. Настоящая линия
между занятиями сохраняет их раздельными.
Тип определяется по оформлению PDF: серый фон — лекция, `lab.` — лабораторная,
все остальные ячейки — семинар.
Варианты `1)` и `2)` в ней становятся отдельными одновременными занятиями для
всей группы. Два преподавателя и две аудитории через `/` в одной паре также
разделяются по порядку. Сохраняется исходный текст ячейки, очевидные строки преподавателя
и аудитории выделяются отдельно. Общие справочники создаются через Prisma.

Если в ячейке `lab. 0.5 gr.` указаны два преподавателя и одна аудитория,
верхний преподаватель назначается на нечётные недели, нижний — на чётные.
Оба занятия сохраняют полный интервал ячейки; такое распределение остаётся
замечанием для сверки в админке. Аудитории с названием корпуса, например
`3-3 Amdaris`, сохраняются целиком.

Проверено на присланном `anul_i_semestrul_i-27.pdf`. Автоматически выделены,
в частности, AM/ALGA по нечётным/чётным неделям и общие лекции нескольких групп.
Это полуавтоматический импорт: сокращения предметов не расшифровываются,
сложные переносы/ячейки могут требовать
объединения или удаления лишней записи. Отдельные ячейки аудитории отмечены
замечаниями. Скан без текстового слоя или другой шаблон может дать пустой
черновик с предупреждением. OCR не реализован. Публикация возможна до сверки
всех записей с оригиналом; замечания при этом сохраняются.

PDF разбирается отдельным процессом с таймаутом 90 секунд; выход ограничен 8 МБ,
число занятий — 2000. Команды не собираются через shell. Неудачный импорт
удаляет загруженный файл и откатывает транзакцию, не создавая частичного набора
таблиц. Загрузка синхронная; для больших объёмов позже нужна очередь задач.

## API и защита

- GET `/api/admin/schedule` — список расписаний и содержимое.
- POST `/api/admin/schedule` — multipart: file/year/course/semester/from/to/first.
- PATCH `/api/admin/schedule/:id` — JSON action: save/publish/unpublish/delete,
  version (updatedAt полученной записи), для save также lessons/holidays.
- GET `/api/admin/schedule/:id/source` — исходный PDF.

Все обработчики проверяют сессию и актуальную роль ADMIN в БД. Мутации
отклоняют чужой Origin. PDF хранится под случайным UUID, путь из запроса не
используется. Ответы не кэшируются. Права на страницу проверяются сервером.
Сохранение и публикация выполняются в транзакции. Общая advisory-блокировка
сериализует изменения и предотвращает двойную публикацию из конкурирующих
запросов. version служит только проверкой устаревшего редактора, истории версий нет.

## Проверка

`playwright.import.config.ts` и `tests/e2e/admin-import.spec.ts` — полный тест
с отдельной настоящей PostgreSQL БД, HTTP, реальным PDF и браузером.
Переменные: IMPORT_TEST_DATABASE_URL (имя БД studyflow_import_test_*),
IMPORT_TEST_PDF, SCHEDULE_PYTHON. К БД предварительно применить миграции.
Запуск: `npx playwright test --config playwright.import.config.ts`.
Набор изолирован от обычных e2e. Тестовые пользователи/справочники остаются
в тестовой БД до её удаления; не запускать на рабочей БД.
