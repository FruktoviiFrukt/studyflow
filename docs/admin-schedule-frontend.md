# Админка расписания: фронтенд

Страница: `/admin/schedule`, ветка `feat/admin-panel`.
Раздел предназначен только для недельного расписания студентов.
Аттестации, экзамены, учебный календарь и бэкенд не входят в эту реализацию.

## Что можно проверить

- При открытии есть два учебных расписания: опубликованное для второго курса и черновик первого курса с одним
  непроверенным занятием. Это тестовые данные, не результат обработки PDF.
- Новый PDF (до 20 МБ) создаёт пустой черновик выбранного года, курса и семестра.
  Проверяются расширение, размер и сигнатура файла. Файл можно открыть для сверки.
- Добавление, редактирование и удаление занятий. Поддерживаются несколько групп
  на одном занятии, вся группа или подгруппы 1/2, семь пар и произвольное время.
- Верхняя половина пары в PDF соответствует нечётной неделе, нижняя — чётной.
- Фильтры по группе, подгруппе, неделе, дню, текстовый поиск и замечания.
  Фильтр нечётной/чётной недели включает занятия, проходящие каждую неделю.
- Предпросмотр студента показывает общие занятия группы и только выбранную
  подгруппу. Время отображается в недельной сетке; можно выбрать один день.
- Непроверенные записи, некорректное время, повторяющиеся получатели и пересечения
  занятий одной группы/подгруппы блокируют демонстрационную публикацию.
  Занятия разных подгрупп или противоположных недель не конфликтуют.
- Демопубликация меняет статус выбранного расписания. Его можно вернуть в
  черновик для правок, не создавая копий. Истории версий и архивирования нет.
- В «Список расписаний» можно удалить черновик вместе с занятиями после
  подтверждения. Другие расписания и исходный PDF на компьютере сохраняются.

## Где заканчивается демонстрация

Все изменения находятся только в React state и исчезают при обновлении страницы
или уходе с неё. PDF остаётся в браузере через object URL; при размонтировании
ресурс освобождается. Нет сетевой загрузки, парсинга PDF, записи в БД, реальной
публикации или изменения студенческой страницы. UI явно сообщает об этом.

Существующий административный layout и его правила доступа не менялись.
Проверку роли ADMIN на сервере нужно реализовать при подключении бэкенда.
Клиентские проверки не заменяют серверную валидацию и контроль доступа.

## Файлы и дальнейшее подключение

- `lib/admin-schedule.ts`: фронтенд-типы, тестовые записи, фильтрация и проверки.
- `components/admin/schedule-manager.tsx`: список расписаний, состояние и действия.
- `schedule-upload.tsx`: выбор PDF и периода.
- `schedule-lesson-editor.tsx`: форма занятия и получателей.
- `schedule-student-preview.tsx`: сетка предпросмотра.

При подключении API заменить источник данных и действия сохранения/публикации.
Названия групп в текущих фронтенд-записях — строки; после согласования профиля
коллеги потребуется сопоставление с ID групп и подгрупп. Нельзя автоматически
считать несколько преподавателей подтверждённым распределением по подгруппам:
импорт должен выдавать такие строки на проверку.

## Проверки

```sh
npm test
npx playwright test --config playwright.admin.config.ts
```

Отдельный Playwright config запускает фронтенд на порту 3101 без БД и тестовой
авторизации. Нужен установленный браузер Playwright; для имеющегося Chrome в
PowerShell можно задать `$env:PLAYWRIGHT_CHANNEL = 'chrome'` перед командой.
Обычные e2e-проверки приложения по-прежнему используют основной config.
