StudyFlow: студенческий ассистент UTM

Глубокий разбор репозитория FruktoviiFrukt/studyflow и всех 17 удалённых веток, состояние на 10 сентября 2026, и план доведения проекта до уровня дипломной работы.

Срез: origin/develop @ 98732c4 Стек: Next.js 16 · React 19 · Tailwind 4 · Prisma 7 · PostgreSQL 16 Проверено локально: lint, tsc, build, 11 юнит-тестов

0. Резюме

За семь дней (4–10 сентября 2026) команда из семи человек собрала полный фронтенд-прототип студенческого кабинета: дашборд, задания, расписание в трёх видах, калькулятор оценок, материалы, AI Exam Coach и страницу входа. Код опрятный, типизирован, проходит lint и сборку. Но это витрина без сервера: все данные захардкожены или живут в памяти вкладки, база данных подключена, но ни одна страница к ней не обращается, а «AI» выбирает вопросы из банка на 15 штук с искусственной задержкой 2,2 секунды.

Главный вывод. Для дипломной работы проекту не хватает не экранов, а системы: доменной модели, персистентности, реальной аутентификации, настоящего AI-контура и измеримого исследовательского вопроса. Всё это достижимо за один учебный год при дисциплине процесса, которая уже частично заложена в ветке imurd (строгий CI, интеграционный тест БД, Playwright, деплой-гейт).

Рекомендуемая тема диплома: «Веб-платформа персонального планирования учёбы с генерацией контрольных вопросов на основе больших языковых моделей (на примере Технического университета Молдовы)». Исследовательское ядро: качество и педагогическая валидность автоматически сгенерированных вопросов, и влияние интервального повторения на результаты самопроверки.

Наблюдения по процессу

  • Скорость высокая, интеграция частая. 14 PR за 7 дней, конфликтов почти нет, потому что каждый работает в своей папке. Это перестанет работать, как только появится общая модель данных.
  • Три несогласованных требования к Node. CI на develop: Node 20. README: «Prisma 7 требует Node 22 LTS». Ветка imurd: .node-version = 24.14.0 и engines: 24.x. Нужен один файл .node-version, на который смотрят и CI, и README.
  • Два контура аутентификации. Страница входа (влита) только пишет данные в console.log. Реальная реализация с Auth.js лежит в отдельной ветке и уже отстаёт. Чем дольше она вне develop, тем дороже слияние.
  • Нет владельца релиза. main пуст, тегов нет, CHANGELOG нет. Для диплома важна воспроизводимая история версий.
  • Ветка imurd как «второй develop». Там свой CI с тремя обязательными джобами, скрипт автосбора всех веток в imurd и деплой на Vercel по SHA. Идея правильная, но применена к личной ветке; её место в develop и в настройках защиты ветки, иначе команда живёт с двумя источниками правды.

3. Архитектура текущего состояния

Приложение целиком клиентское поверх Next.js App Router. Серверный код исполняется только для рендера страниц. Слой lib/ содержит чистые функции и демо-фикстуры, а не доступ к данным.

Что сделано хорошо

  • Чистое разделение UI и логики в тех модулях, где логика есть: валидация заданий, парсер формул оценок и утилиты дат живут в lib/ и покрыты тестами.
  • Безопасный парсер формул в lib/grades.ts: рекурсивный спуск с поддержкой процентов, скобок и приоритета, без eval, с ограничением длины и диапазона результата. Это готовый материал для главы диплома про обработку пользовательского ввода.
  • Корректная работа с датами расписания: часовой пояс Europe/Chisinau, date-only арифметика в UTC, чтобы переход на летнее время не сдвигал неделю, force-dynamic для «сегодня».
  • Доступность: aria-атрибуты, фокус на первой ошибке формы, aria-live для статуса формулы, клавиатурная навигация в мобильном меню, проверенная e2e-тестом в ветке imurd.
  • Компонентная база на Radix + CVA (button, card, dialog, badge, progress, segmented-control) с токенами shadcn в globals.css.

Что архитектурно отсутствует

  • Слой доступа к данным: ни одного Route Handler, Server Action или репозитория.
  • Доменная модель: единственная сущность в Prisma это User. Предметы, группы, занятия, задания, материалы, оценки, тесты не смоделированы.
  • Идентичность пользователя: все страницы показывают «Student / student@utm.md».
  • Хранилище файлов: материалы держатся в памяти как объекты File и исчезают при перезагрузке.
  • AI-контур: нет вызова модели, нет извлечения текста из PDF/DOCX, нет хранения истории попыток.
  • Наблюдаемость и безопасность: нет логирования, rate-limit, security-заголовков, CSP.

4. Разбор модулей

4.1 Dashboard

Серверный компонент со статическими массивами: три занятия, три дедлайна, четыре предмета с процентами, четыре быстрых действия. Числа в карточках («12 выполнено», «18 файлов») не связаны ни с чем. Компонент SummaryCard хорош, страницу нужно перевести на агрегаты из БД: занятия на сегодня по группе, ближайшие дедлайны пользователя, доля выполненных заданий за семестр.

4.2 Задания (Tasks)

Самый зрелый модуль по UX: три статуса с циклическим переключением, приоритеты, фильтры, прогресс по предмету, диалог создания/редактирования с валидацией, подтверждение удаления, управление списком предметов. Валидация календарных дат (29 февраля, 31 апреля) вынесена и протестирована.

  • Файл страницы 765 строк: в нём собственный CustomSelect, хотя components/ui/select.tsx на Radix уже существует. Нужно разнести на компоненты и убрать дубль.
  • Идентификаторы number с Math.max + 1; при переходе на БД станут cuid.
  • Список предметов дублируется в 6 файлах (dashboard, tasks, materials ×2, grades, schedule). Это первый кандидат на общую сущность Subject.
  • Признак «Просрочено» считается по локальному времени браузера, а расписание по времени университета. После появления сервера правило нужно одно.

4.3 Расписание (Schedule)

Три представления: личное (неделя/день с date picker), аттестации и экзамены, глобальное по курсам и группам. Утилиты дат корректны и протестированы. Данные: demoWeek из 14 шаблонных занятий, повторяющихся каждую неделю; глобальное расписание генерируется процедурно из списка групп 3-го курса, взятого из PDF public/schedules/year-3-semester-5.pdf.

  • Комментарии в коде честно говорят: «Replace this provider with dated API records». Это правильный контракт для будущего сервера.
  • Реальный источник расписания UTM это PDF на сайте факультета. Импорт расписания (парсер PDF → структурированные записи с проверкой человеком) может стать самостоятельным инженерным разделом диплома.
  • Нужны понятия: семестр, неделя чётная/нечётная, подгруппа, исключения (перенос, отмена), которых в типе Lesson нет.

4.4 Средний балл (GPA)

Пять этапов по умолчанию (аттестация 1 и 2, лабораторные, индивидуальная работа, экзамен) с весами 15/15/15/15/40 и редактируемой формулой на предмет. Фильтр по семестрам, предупреждение об оценках ниже 5, общий средний балл. Хорошая тестовая обвязка: границы, деление на ноль, инъекции, неполные данные.

  • Хранение только в состоянии компонента.
  • Роль преподавателя упоминается в истории коммитов («read-only teacher grades page»), но в Prisma есть только STUDENT и ADMIN.
  • Для UTM стоит уточнить формулу итоговой оценки по регламенту (часто 60% текущая + 40% экзамен, вариативно по кафедрам) и зашить её как пресет, оставив редактор.

4.5 Материалы (Materials)

Загрузка через drag-and-drop до 50 МБ, группировка по предметам, поиск, оглавление, открытие и скачивание через URL.createObjectURL, удаление с подтверждением. Кнопка «Подготовить с ИИ» ведёт на /ai-coach?material=…, но параметр никто не читает.

  • Нужно объектное хранилище (S3-совместимое, локально MinIO) и таблица Material с владельцем, предметом, MIME, размером, хэшем.
  • Есть вторая копия formatFileSize (первая в lib/ai-coach.ts) с другой логикой округления.
  • Материалы это естественный вход для AI Coach: загруженный конспект должен становиться источником вопросов.

4.6 AI Exam Coach

Трёхшаговый сценарий: настройка (заметки файлом или текстом, предмет, количество 5–20, сложность, тип вопроса) → тест с прогрессом → результаты с сильными и слабыми темами и «XP». Экранная логика аккуратная; проблема в содержимом.

  • handleGenerate ждёт 2,2 секунды и берёт вопросы из банка на 15 штук (по 3 на предмет); при запросе 20 вопросов дублирует их с суффиксом -r1. Загруженный файл никак не читается.
  • Типы QuestionType определены дважды с разными значениями (single | true-false в lib и multiple-choice | true-false в types) и конвертируются вручную.
  • Нет хранения попыток, поэтому «Проработать слабые темы» просто перезапускает тот же тест.
  • Это тот модуль, который делает работу дипломной, а не курсовой: ниже он расписан отдельно.

4.7 Аутентификация

В develop: красивая страница с табами, показом пароля, «запомнить меня» и «забыли пароль» без обработчиков; сабмит пишет в консоль. Кнопка «Выйти» это ссылка на /auth.

В feature/backend/auth: Auth.js v5 (beta) с Credentials-провайдером, bcrypt, JWT-сессии, роут регистрации, proxy.ts с редиректами для защищённых путей, сид администратора, типизация сессии с ролью. Формы подключены к signIn, шапка и сайдбар показывают реальное имя.

  • Замечания к ветке: email не нормализуется (регистр, пробелы), нет ограничения частоты запросов, невалидный JSON даст 500, пароль администратора по умолчанию admin123 допустим только в dev и должен падать в production без переменной окружения. Нет восстановления пароля и подтверждения email.
  • next-auth 5 всё ещё beta. Альтернатива для диплома: Better Auth или собственный минимальный слой на jose. Решение стоит зафиксировать в ADR.

4.8 Инфраструктура и CI

  • Docker Compose с PostgreSQL на 5433, Prisma 7 с драйвер-адаптером @prisma/adapter-pg, миграция init с таблицей User. README подробно описывает установку под Windows/WSL2.
  • CI на develop: один джоб, lint + build, без тестов, без typecheck, без Prisma. Ветка imurd содержит целевой вариант: Quality (format, lint, typecheck, unit, build), Database (реальный Postgres, migrate deploy, интеграционный тест), Browser (Playwright, 4 сценария), артефакты отчётов, деплой-гейт по SHA.

  • Пока нет сервера, поверхность атаки минимальна. Парсер формул и валидация заданий сделаны с оглядкой на инъекции.
  • После слияния auth: нужны rate-limit на /api/auth/*, нормализация email, единая zod-валидация тела запроса, security-заголовки (CSP, HSTS, frame-ancestors), проверка владельца на каждом запросе к данным, аудит зависимостей в CI (npm audit --omit=dev или OSV-scanner).
  • Секреты: .env* в gitignore, пример без значений, в imurd есть .vercelignore. Хорошо.

6. Реестр находок

Приоритет: P1 блокирует развитие или ломает поведение · P2 технический долг, который дорожает · P3 гигиена.

F-01P1 Неверный импорт cn из npm-пакета «cn»

В components/ui/input.tsx и components/ui/select.tsx написано import { cn } from "cn". Это сторонний пакет cn@0.2.6, а не утилита проекта из lib/utils.ts. Сейчас сборка проходит, потому что эти компоненты нигде не используются, но первый же импорт даст неверную склейку классов.

7. Целевая архитектура

Принцип: остаться в одном репозитории и одном рантайме Next.js, но ввести явные слои. Отдельный микросервис оправдан только для тяжёлой обработки документов и вызовов модели, и то во второй фазе.

Ключевые решения (кандидаты в ADR)

Решение Рекомендация Почему
Транспорт клиент–сервер Server Actions для мутаций, Route Handlers для файлов и внешних клиентов Минимум кода, типобезопасность end-to-end; REST остаётся там, где нужен стриминг или загрузка.
Валидация zod-схемы в lib/schemas, общие для клиента и сервера Убирает дубли валидации, даёт OpenAPI бесплатно.
Аутентификация Auth.js v5 (уже написано) с планом миграции на Better Auth, если beta не стабилизируется к декабрю Не переписывать готовое; зафиксировать риск.
Файлы S3-совместимое хранилище, presigned URL, локально MinIO в docker-compose Не держать байты в Postgres и в памяти; одинаково работает локально и в облаке.
Фоновые задачи pg-boss поверх той же PostgreSQL Генерация вопросов занимает секунды и должна идти вне HTTP-запроса; без Redis.
Модель Сильная модель для генерации, компактная и дешёвая для валидации и классификации тем; structured output по JSON-схеме вопроса; провайдер за адаптером Качество генерации против стоимости проверки; схема исключает «сломанный» JSON.
Хостинг Vercel для приложения (уже подготовлено в imurd), Neon или Supabase для Postgres, Cloudflare R2 для файлов Бесплатные тарифы покрывают дипломный масштаб.
Локализация next-intl, ru/ro/en, начиная с фазы 3 UTM двуязычен; для защиты на румынском важно.

10. Исследовательская часть диплома

Инженерная работа без измеримого вопроса остаётся курсовым проектом. Ниже две связанные гипотезы, которые проект способен проверить на собственных данных.

Гипотеза A. Качество автоматически сгенерированных вопросов

  • Вопрос: какая стратегия генерации даёт больше педагогически валидных вопросов при одинаковом бюджете: (1) полный конспект в контекст, (2) RAG по чанкам, (3) генерация + отдельный валидатор.
  • Данные: golden-набор из 10 конспектов по 5 предметам FCIM, по 20 вопросов на конспект и стратегию, итого около 600 вопросов.
  • Метрики: доля вопросов, прошедших валидатор; доля корректных по оценке двух преподавателей (каппа Коэна для согласия); распределение по уровням Блума; доля «утечки ответа» в формулировке; стоимость и латентность на вопрос.
  • Метод: слепая экспертная оценка по рубрике из 5 критериев; статистика: тест хи-квадрат по долям, доверительные интервалы.

Гипотеза B. Эффект интервального повторения

  • Вопрос: повышает ли SM-2 расписание повторений точность ответов на отложенном тесте через 2 недели по сравнению со свободной самопроверкой.
  • Дизайн: две группы студентов (внутри пилота), одинаковый материал, контроль через 14 дней; сравнение долей правильных ответов (t-критерий или Манна–Уитни), размер эффекта Коэна.
  • Ограничения: малая выборка, самоотбор; честно описать в главе об ограничениях.

Метрика Как измеряется Цель для пилота
