# Расчёт расписания по датам — пункт 3

Реализован в `lib/server/student-schedule.ts`. Это функция над загруженными
сервером данными, без обращений к БД и без изменений записей. Тип входных
расписаний выводится из Prisma. Миграция для этого шага не нужна.

## Контракт

`calculateStudentSchedule({ from, to, student, schedules })` принимает:

- `from`, `to` — существующие даты YYYY-MM-DD, включительно, максимум 366 дней;
- `student.groupId` и `student.subgroup: { id, groupId }`, полученные сервером
  из профиля; не передавать сюда непроверенный профиль из браузера;
- расписания с `semester.academicYear`, `holidays`, `lessons.subject` и
  `lessons.audiences`. Загружать получателей группы без фильтра по дню или
  чётности: они также определяют принадлежность расписания группе.

Результат: `PROFILE_REQUIRED` при неполном профиле или `READY` с массивом дней.
Каждый день содержит дату, расписание, номер/чётность учебной недели, каникулы,
занятия и один из статусов:

- `NOT_PUBLISHED` — нет применимого опубликованного расписания;
- `HOLIDAY` — каникулы/выходной, занятия скрыты;
- `NO_LESSONS` — расписание есть, подходящих занятий нет;
- `LESSONS` — занятия есть.

Пустое расписание без получателей не определяет группу, поэтому не считается
опубликованным расписанием этой группы. Проверка публикации должна запрещать
пустые расписания. Два применимых опубликованных расписания одной группы на
одну дату вызывают ошибку, чтобы не смешивать данные молча.

## Правила

Функция пересекает даты действия расписания, семестра и учебного года. Недели
считает от понедельника первой нечётной недели; до этой даты занятия не выдаются.
Каникулы и смена семестра не сбрасывают счётчик. Каждое занятие выдаётся один
раз за дату, даже если у него несколько подходящих получателей. Результат
сортируется по дате и времени; ID экземпляра состоит из ID занятия и даты.

Даты PostgreSQL DATE передаются как Date в полночь UTC. Время пар остаётся в
минутах местного времени университета, без преобразования в часовой пояс браузера.
Текущую дату будущая страница получает через существующую `universityToday()`.

Отдельная `academicWeek(date, firstOddWeekMonday)` возвращает номер и чётность;
до первой недели возвращает null. Некорректные даты/границы вызывают RangeError,
чужая подгруппа и конфликт публикаций — Error. HTTP-коды определит будущий API.

## API

Защищённый `GET /api/schedule` реализован. Он проверяет сессию,
читает текущий профиль и расписания через Prisma и вызывает эту функцию.
Контракт описан в `student-schedule-api.md`. К странице API пока не подключён.

## Где будет импорт PDF (предлагаемые файлы, ещё не реализованы)

1. `app/api/admin/schedule/import/route.ts` — проверка ADMIN, размера/типа файла
   и выбранного учебного периода, сохранение PDF в файловом хранилище.
2. `lib/server/schedule-import/parse-pdf.ts` — извлечение текста и геометрии
   таблицы, определение групп, дней, интервалов и объединённых ячеек.
3. `lib/server/schedule-import/normalize.ts` — перевод результата в предметы,
   недельные правила и получателей; верхняя половина пары ODD, нижняя EVEN.
   Неоднозначные подгруппы остаются замечаниями для проверки, а не угадываются.
4. `lib/server/schedule-import/save-draft.ts` — после проверки формата данных
   транзакция Prisma: справочники, ScheduleImport со статусом DRAFT, Lesson,
   LessonAudience. Хранить sourceFileKey; не сохранять временный browser blob URL.
5. Админский API редактирования и публикации — ручные исправления, проверка
   полноты/пересечений и транзакционный перевод в PUBLISHED. При замене действующего
   расписания исключить двойную публикацию. При ошибке разбора сохранить исходник
   и показать ошибку/замечания, не публиковать частично распознанные данные.

Конкретную библиотеку и способ выполнения (в запросе или отдельной фоновой задаче)
выбрать при реализации по реальным PDF и времени обработки. Не требуется
разбирать PDF при открытии студентом страницы: она читает записи из БД.

Порядок работ: API на проверенных тестовых данных → подключение страницы →
импорт PDF и проверка в админке. Парсер можно делать параллельно после фиксации
формата данных. Для него нужны реальные PDF разных курсов с трудными случаями.
