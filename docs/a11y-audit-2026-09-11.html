3. Три версии дизайна

Это ступени, а не альтернативы. Каждая следующая строится на токенах предыдущей.

Версия A · ≈ 24 ч

AA без редизайна

До октябрьского дедлайна. Пользователь визуально почти ничего не заметит.
  • Токены с ролями: текст не светлее -600, иконки не светлее -500, статусы -700. Семантические --success/--warning/--danger.
  • Один глобальный :focus-visible 2px с offset вместо 27 вариантов outline-none. scroll-margin-top под липкую шапку.
  • Skip-link, main#main, title для 4 маршрутов, один владелец h1, проп as у CardTitle/EmptyState.
  • CustomSelect → Radix, AuthTabs → tablist, квиз → radiogroup, DialogClose 36px.
  • role="status" в LoadingIndicator, role="alert" в ErrorState, анонс генерации, фокус на новый экран.
  • Глобальный prefers-reduced-motion; axe в Playwright как гейт CI.
Версия B · ≈ 26 ч

Режимы восприятия

1–2 недели после A. Компоненты не переписываются, меняются только токены.
  • Тёмная тема: 15 классов dark: сейчас мёртвые, токенов нет. [data-theme] + prefers-color-scheme.
  • Высокий контраст: границы gray-700, чёрный на белом, фокус 3px, prefers-contrast: more.
  • Масштаб текста 100/112/125 %. Убрать text-[10px] и text-xs из смыслового текста (76 мест). Reflow на 320px и 200 %.
  • Диалоги с max-h-[85dvh] overflow-y-auto.
  • Страница «Настройки → Доступность»: тема, контраст, размер, анимация. localStorage, потом профиль.
Версия C · семестр

Инклюзивный редизайн

Глава диплома: доступность как исследуемое свойство.
  • Дашборд как упорядоченный список приоритетов, карточки как article с dl.
  • Расписание в трёх представлениях: таблица, список по дням, «только сегодня» крупно.
  • Квиз без гонки: один вопрос на экран, текстовая обратная связь, «Объяснить», без таймера как принцип.
  • Цели 44×44 на мобильном, шрифт с открытыми формами вместо Arial (Geist объявлен, но не подключён), режим «дислексия».
  • Язык частей: lang="en" для английских строк, подготовка RO/EN.
  • Тест с 5–8 студентами: клавиатура, NVDA/VoiceOver, зум 200 %. Метрики: время, ошибки, SUS.

5. Что сделано хорошо и должно остаться эталоном

  • week-grid.tsx, global-schedule.tsx: настоящая таблица, th scope, aria-current="date", прокручиваемая область с именем.
  • task-dialog.tsx: htmlFor/id, aria-invalid, aria-describedby → role="alert", фокус на первое невалидное поле.
  • subject-cards.tsx: полный progressbar с aria-valuetext «8,5 из 10» и единственный motion-reduce.
  • subject-card.tsx в AI Coach: правильный radiogroup, образец для квиза.
  • lesson-card.tsx: карточка-кнопка с полным aria-label и явным кольцом фокуса.
  • Ни один статус в задачах, оценках и расписании не передаётся только цветом.
  • Навигация: aria-current, aria-expanded/aria-controls через useId.

7. Как воспроизвести axe

Добавить @axe-core/playwright в devDependencies и спек в tests/e2e/. Он встанет в существующий job браузерных тестов. 

import { test, expect } from "@playwright/test";
import AxeBuilder from "@axe-core/playwright";

const routes = ["/dashboard", "/tasks", "/schedule", "/schedule/global",
  "/schedule/assessments", "/gpa", "/gpa/calculator", "/materials", "/ai-coach"];

for (const route of routes) {
  test(`a11y ${route}`, async ({ page }) => {
    await page.goto(route);
    const { violations } = await new AxeBuilder({ page })
      .withTags(["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22aa"])
      .analyze();
    expect(violations, JSON.stringify(violations, null, 2)).toEqual([]);
  });
}

axe не видит клавиатуру, фокус и живые регионы. Раздел 6 остаётся ручным чек-листом при ревью PR.
