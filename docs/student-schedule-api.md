# API расписания студента

`GET /api/schedule?from=2026-09-14&to=2026-09-20`

Обе даты обязательны, границы включительны. Максимум 366 дней. Повторяющиеся
и посторонние параметры (включая userId/groupId/subgroupId) отклоняются.

## Обработка

- `app/api/schedule/route.ts` подключает Auth.js и Prisma к обработчику
  `lib/server/schedule-api.ts`. Работает в Node.js, без статического кэширования.
- Проверка сессии выполняется в самом API, независимо от proxy.ts. Из сессии
  используется только ID пользователя. Группа читается заново из БД.
- Удалённый пользователь считается неавторизованным. Администратор без учебной
  группы получает PROFILE_REQUIRED: этот адрес не является админским просмотром.
- Если нет `groupId`, API ищет сохранённое название `User.group` в справочнике
  групп. Если группу найти не удалось, возвращается PROFILE_REQUIRED без запроса
  занятий.
- Prisma выбирает опубликованные расписания типа STUDENT для группы с пересекающимися периодами
  действия, семестрами и годами. Каникулы ограничены запрошенными датами.
- Загружаются все занятия группы. Параллельные варианты 1) и 2) из PDF
  показываются вместе, выбор подгруппы студенту не нужен.
- `calculateStudentSchedule` рассчитывает даты, чётность и каникулы; наружу
  возвращаются только данные отображения, без PDF-ключей, пароля или email.
- Ответы имеют Cache-Control: private, no-store и Vary: Cookie.

## Ответы

| HTTP | Содержимое                                                                 |
| ---- | -------------------------------------------------------------------------- |
| 200  | status: READY, from, to, timeZone, group, days                             |
| 200  | status: PROFILE_REQUIRED, message, те же метаданные, days: []              |
| 400  | code: INVALID_RANGE, message — некорректные параметры                      |
| 401  | code: UNAUTHORIZED, message — нет сессии/пользователя                      |
| 409  | code: SCHEDULE_CONFLICT, message — несколько действующих расписаний группы |
| 500  | code: INTERNAL_ERROR, message — сбой БД или неверные сохранённые данные    |

`group` содержит id/name. Поля дней и занятий
описаны в `student-schedule-calculation.md`. Нет публикации — успешный ответ
READY с NOT_PUBLISHED для соответствующих дат. Нет занятий — NO_LESSONS;
каникулы — HOLIDAY. Ошибки не содержат внутренние исключения или адрес БД.

## Проверка

`tests/schedule-api.test.mjs` вызывает тот же обработчик с изолированными
подстановками сессии и БД: проверяет доступ, входные параметры, запрос Prisma,
актуальность профиля, вычисленный результат, конфликты и безопасные ошибки.
Запуск: `npm test`. Это не проверка HTTP на работающем сервере с настоящей БД.

После применения миграций и запуска приложения адрес можно открыть в браузере
с активной сессией. Для READY нужен заполненный groupId в профиле.
Для занятий — опубликованные записи БД. GET ничего не создаёт и не меняет.

Новой миграции нет. Страница `/schedule` подключена к API;
см. `student-schedule-page.md`.
Выбор подгруппы в профиле для расписания не требуется.
